# Claude Code 向け手順書：「Lステップ ログアウト記録」を導入する

> この手順書は **Claude Code が読んで実行するためのもの** です。ユーザーと会話しながら、上から順に進めてください。
> 配布元（人間向けの解説ページ）：https://ryoya9595.github.io/rise-guide/lstep-logout-watch/

---

## 0. ゴールと前提

ユーザーは「Lステップの管理画面から、1日に1〜3回、急にログアウトされる」問題で困っている。原因はまだわかっていない。

このキットは、ユーザーのChromeに **自分専用の小さな拡張機能「Lステップ ログアウト記録」** を入れて、次のことを数日間記録する。

- ログイン画面に飛ばされた **時刻** と、その直前に開いていたページ
- **最後に操作してから何分後** に追い出されたか（放置による時間切れかどうかの判定用）
- ログイン情報（Cookie）が **どう消えたか**（Lステップ側が消した／有効期限切れ／ブラウザ側で消された／Chromeの容量整理）
- ログイン画面に出ていた **注意書き**（例：「他の端末でログインされました」）

数日分の記録を見れば「同じIDで別の人がログインしている」「ログインの有効時間が短い」「パソコン側でCookieが消されている」のどれなのかを絞り込める。

### 安全面（ユーザーに説明すること）
- Cookieの **中身（値）は読まない・残さない**。残すのは名前・時刻・消え方だけ
- 操作については「最後に操作した時刻」だけを残す。何を押したか・何を入力したかは見ない
- 記録は **このパソコンのChromeの中だけ** に保存し、どこにも送信しない（拡張機能に外部へ通信する処理は入っていない）
- 動くのは linestep.net のページだけ。他のサイトは見ない
- いつでも削除できる（下の「6. やめ方」）

### Claude Code へのお願い
- 拡張機能のファイルは **下のURLからそのまま取得** する。中身を書き換えたり、自分で作り直したりしない
- ユーザーのChromeを自動操作しない（拡張機能の読み込みはユーザー本人が画面で行う）
- `.env`・パスワード・Cookieの値など、機密情報は読まない・聞かない

## 1. 最初にユーザーに確認すること

作業を始める前に、次の2つを聞いてください（答えはこのあとの説明に使う）。

1. 「このパソコンにChrome用の小さな拡張機能（Lステップのログアウトを記録するだけのもの）を入れて、数日動かしてもいいですか？」→ OKが出たら進む
2. 「Lステップのログインは、ほかの人（りょうやさん・スタッフなど）と **同じID** を使っていますか？」
   - 「同じIDを使っている」→「それが原因かもしれません。サービスによっては、同じIDで別の場所からログインされると、先にログインしていた方を追い出すことがあります。Lステップがそうなっているかは、記録を取ればはっきりします」と伝えてから進む
   - 「自分専用のID」「わからない」→ そのまま進む

## 2. ファイルを取得する

保存先は、ユーザーのホームフォルダの `lstep-logout-watch`（Mac：`~/lstep-logout-watch`／Windows：`%USERPROFILE%\lstep-logout-watch`）。すでに同じ名前のフォルダがあれば、中身を確認してユーザーに上書きしてよいか聞く。

取得するファイル（5つ）。元の場所：`https://ryoya9595.github.io/rise-guide/lstep-logout-watch/ext/`

| ファイル | 役割 |
|---|---|
| `manifest.json` | 拡張機能の設定 |
| `background.js` | 記録係（ログアウトの瞬間を記録） |
| `content.js` | ログイン画面の注意書きを読む係 |
| `log.html` | 記録を見るページ |
| `log.js` | 記録を見るページの動き |

**Mac（ターミナル）**
```bash
mkdir -p ~/lstep-logout-watch && cd ~/lstep-logout-watch
for f in manifest.json background.js content.js log.html log.js; do
  curl -fsSL -o "$f" "https://ryoya9595.github.io/rise-guide/lstep-logout-watch/ext/$f" || echo "失敗: $f"
done
ls -la
```

**Windows（PowerShell）** ※ `curl` ではなく `curl.exe` を使う
```powershell
$d = "$env:USERPROFILE\lstep-logout-watch"; New-Item -ItemType Directory -Force -Path $d | Out-Null
foreach ($f in "manifest.json","background.js","content.js","log.html","log.js") {
  curl.exe -fsSL -o "$d\$f" "https://ryoya9595.github.io/rise-guide/lstep-logout-watch/ext/$f"
}
Get-ChildItem $d
```

### 取得できたかの確認
- 5つのファイルが揃っていて、どれも0バイトではないこと
- `manifest.json` の中に `"name": "Lステップ ログアウト記録"` があること（文字化けしていないこと）
- 揃っていなければ、もう一度取得する。それでもダメなら、ネットワークの問題としてユーザーに伝える

## 3. Chromeに読み込む（ユーザーに画面でやってもらう）

ここはユーザー本人の操作が必要。1ステップずつ案内し、できたか確認しながら進める。

1. 先にフォルダを開いておく
   - Mac：`open ~/lstep-logout-watch`
   - Windows：`explorer $env:USERPROFILE\lstep-logout-watch`
2. Chromeのアドレスバーに `chrome://extensions` と打ってEnter（リンクのクリックでは開けないので、手で打つ）
3. 右上の **「デベロッパーモード」** をオンにする
4. 左上に出てくる **「パッケージ化されていない拡張機能を読み込む」** を押す
5. フォルダを選ぶ画面で `lstep-logout-watch` フォルダを選んで「選択」
   - Mac で場所がわからないとき：その画面で `Cmd + Shift + G` を押し、`~/lstep-logout-watch` と入力してEnter
6. 一覧に **「Lステップ ログアウト記録」** が出ればOK。エラーが出たら、表示された文言をそのまま教えてもらう
7. アドレスバー右のパズルのアイコン →「Lステップ ログアウト記録」のピンを押して、ツールバーに出しておく

### 動作確認
- ツールバーの拡張機能アイコンを押すと「Lステップ ログアウト記録」のページが開き、「記録開始」が1行出ていれば成功
- Lステップの管理画面を一度開き直しておく（すでに開いているタブは、再読み込みすると記録の対象になる）

## 4. ユーザーに伝えること（導入後）

次の内容を、ユーザーにわかりやすく伝えて終わる。

- **3〜4日、いつもどおりLステップを使ってください。** 特別な操作はいりません
- 急にログアウトされたら、拡張機能のアイコンに赤い数字が付きます（回数）
- できれば、ログアウトされたときに「何をしていたか」「他の人がLステップを触っていそうな時間か」をメモしておくと、原因が早く見つかります
- 数日たったら、アイコンを押して記録ページを開き、**「記録をコピー（送る用）」** を押して、りょうやさん（またはこのClaude Code）に貼り付けて送ってください
- Chromeの「デベロッパーモードの拡張機能を無効にする」という案内が出ても、そのまま閉じて大丈夫です

## 5. 記録を読むとき（ユーザーが記録を貼ってきたら）

ユーザーが記録を貼ってきたら、次の見方で原因を整理して、わかりやすく伝える。断定できないときは「可能性が高い」と言う。

まず「ログイン画面に戻された」の行ごとに、**最後の操作から何分後か** と **ログイン情報が消えたか** を見る。

| 記録に出るもの | 意味 | 考えられる原因 |
|---|---|---|
| 「最後の操作から○分後」が毎回だいたい同じ（例：25〜35分） | 放置していると切れる | **放置による時間切れ**（Lステップ側の仕様）。こまめに画面を開き直す／Lステップに有効時間を問い合わせる |
| 「最後の操作から1分以内」（操作中に追い出される） | 使っている最中に無効にされた | 時間切れではない。**同じIDでの別ログイン**か、**ネットのつなぎ先（IP）の変化**が有力。時刻を、他の人のログイン時間やWi-Fi切り替えと比べる |
| 「ログイン情報：消えていない（Lステップ側でログインが無効になった）」 | パソコンにはログイン情報が残っているのに、Lステップのサーバーが無効と判断した | 原因はパソコン側ではなく**Lステップ側**。上の放置時間と組み合わせて判断する |
| ログイン画面のメッセージに「他の端末」「別の場所」「同時ログイン」など | Lステップが同時ログインを検知して追い出した | **同じIDを複数人で使っている**。スタッフごとにIDを分けると解決 |
| 「ログイン画面に戻された」の直前に「消えた：Lステップ側が消した」 | Lステップのサーバーがログインを取り消した | 同じIDでの別ログイン／ログインの有効時間切れ／ネットのつなぎ先（IP）が変わった（Wi-Fiの切り替え・VPN・テザリングなど）。時刻を、他の人がLステップを触った時間や、移動・Wi-Fi切り替えの時間と比べる |
| 「消えた：有効期限切れ」が毎回だいたい同じ間隔 | ログインの有効時間が来て切れた | Lステップ側の仕様。「ログイン情報の控え」に出ている期限と比べる。ユーザー側では直せないので、Lステップのサポートに問い合わせる |
| 「消えた：ブラウザ側で消された」 | Chrome側でCookieが消された | 閲覧データの自動削除の設定、Cookieを消す拡張機能（広告ブロック・プライバシー系・クリーナー系）、セキュリティソフト。`chrome://settings/content/all` やインストール済み拡張機能を一緒に確認する |
| 「消えた：Chromeの容量整理」 | Chromeが古いCookieを整理した | まれ。続くようならChromeの閲覧データを一度整理する |
| 「Chrome起動」の直後に毎回ログアウト | Chromeを閉じるとログインが消えている | 「Chromeを閉じるときにCookieを削除する」設定がオンになっていないか確認 |

時刻の比較が大事なので、ログアウトされた時刻を一覧にして、「同じIDを使っている人がその時間にログインしたか」を確かめるよう提案する。

記録だけで理由が決まらないとき（操作中に追い出され、注意書きもなく、ログイン情報も消えていない場合など）は、**ログアウトされた正確な日時の一覧** を作って、Lステップのサポートに「この日時に急にログアウトされた。サーバー側の理由を調べてほしい」と問い合わせる文面を用意する（送るのはユーザー本人）。

「最後の操作：不明」は、Chromeを起動してからLステップを一度も操作していないまま追い出された場合に出る。

---

## 6. やめ方（記録が取れて不要になったら）

1. `chrome://extensions` を開き、「Lステップ ログアウト記録」の **「削除」** を押す（記録も一緒に消える。必要なら先に「記録をコピー」しておく）
2. `lstep-logout-watch` フォルダを削除する
3. デベロッパーモードは、ほかに使っていなければオフに戻してよい
